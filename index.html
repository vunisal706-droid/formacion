IA en el cole

Herramientas hechas con inteligencia artificial para planificar, evaluar, convivir y reunirnos. Hoy verás cómo funcionan, cómo llevarlas a tu centro y cómo crear las tuyas.

Lo que vamos a hacer hoy

  1. Conocer las appsQué problema resuelve cada una y cómo se usa en el día a día.
  2. Entender cómo están hechasUn archivo, una base de datos gratuita y una web pública.
  3. Llevarlas a tu centroDescargar, conectar con el Firebase del centro y publicar.
  4. Crear la tuya con IAUn Gem de Gemini que te acompaña desde la idea hasta la app.

Diez apps, un mismo patrón

Todas nacieron de una necesidad concreta del centro y todas son un único archivo HTML. Unas guardan en el navegador y otras en Firebase para compartir datos. Si entiendes una, entiendes todas.

Cómo se hace una app así

NecesidadAlgo que hoy haces con papel, correos o una hoja de cálculo.
Conversación con IADescribes el problema y la IA escribe el código.
Un solo archivoindex.html: diseño, textos y funciones juntos.
FirebaseLa base de datos donde se guardan y comparten los datos.
GitHub PagesLa publica con una dirección web gratuita.

No hace falta saber programar. Hace falta saber qué quieres y tener paciencia para probar.

Qué necesitas para llevártelas

Una cuenta de Google del centro

Para crear el proyecto de Firebase. Mejor del centro que personal: si cambias de destino, la app sigue.

Una cuenta de GitHub

Gratuita. Es donde se publica la app para abrirla desde cualquier dispositivo.

Una tarde tranquila

Para la primera app con base de datos. Las que guardan en el navegador funcionan nada más descargarlas.

Coste: el plan gratuito de Firebase suele bastar para el uso normal de un centro.

Tres reglas antes de empezar

Ningún dato personal en el código

La web es pública. Nombres, usuarios y notas van en la base de datos, nunca dentro del HTML.

Reglas de seguridad siempre

Cada app trae sus reglas. Una base de datos sin reglas está abierta a cualquiera.

No sustituyen a Séneca

Ayudan a organizar y analizar. Lo oficial se sigue registrando donde corresponde.

Manos a la obra

Empieza por ver las apps en marcha, elige una y conéctala con tu centro siguiendo los pasos.

1 / 7

Usa las flechas del teclado para avanzar y la tecla F para pantalla completa.

Las apps

Pulsa Ver para abrir la versión de demostración. Descargar te da la plantilla limpia, sin datos de ningún centro. Las que no usan base de datos funcionan nada más descomprimirlas; las demás se conectan con el Firebase de tu centro en la pestaña Configurar. El botón del código QR sirve para abrirla en el móvil durante la sesión.

Configurar una app para tu centro

Todo ocurre en tu navegador: el archivo no se sube a ningún sitio. Las apps con base de datos necesitan además el bloque de configuración de tu proyecto de Firebase (lo tienes explicado en Guías paso a paso). Cuadra Horarios, Mis Lecturas, PDF a Markdown y Word y el Troglodita no necesitan configuración.

Sube la plantilla

El index.html de la app. Si descargaste un .zip, descomprímelo primero.

Pega la configuración de Firebase

En la consola de Firebase: ⚙ Configuración del proyecto → Tus apps → copia el bloque const firebaseConfig = {…} completo y pégalo tal cual.

Datos del centro

Se guardan en este navegador para no tener que repetirlos con la siguiente app.

Aparecerán cuando subas la plantilla.

Descarga la app

El archivo descargado sustituye al index.html de la plantilla. Súbelo a GitHub junto con el resto de archivos del zip.


          
        

        
      

      

    

  







  

    
Guías paso a paso

    
En orden, de la cuenta vacía a la app publicada. Los nombres de los menús pueden variar un poco según el idioma de tu consola.

  


  

    
Poner una app en marcha


    

      
1. Crear el proyecto de FirebaseSolo para Evaluaciones, ConVive y Teletrabajo

      

        
    
          
  1. Entra en console.firebase.google.com con la cuenta de Google del centro.
    2. 
          
  2. Pulsa Crear un proyecto y ponle un nombre claro, por ejemplo teletrabajo-losolivos. Google Analytics no hace falta: puedes desactivarlo.
    3. 
          
  3. Ya dentro del proyecto, activa primero la base de datos (guía 2, o 2 bis para ConVive). Así el bloque de configuración traerá la dirección de la base de datos.
    4. 
          
  4. En la portada del proyecto pulsa el icono web </> para registrar una app. Ponle un apodo y no marques Firebase Hosting.
    5. 
          
  5. Copia el bloque const firebaseConfig = {…}. Es lo que pegarás en el configurador. Siempre puedes volver a verlo en ⚙ Configuración del proyecto → Tus apps.
    6. 
        

        
Un proyecto por app. Cada proyecto tiene sus propias reglas de seguridad; si mezclas dos apps en uno, las reglas de una pueden romper la otra.

      

    


    

      
2. Activar Realtime DatabaseDonde se guardan los datos

      

        
    
          
  1. Menú lateral: Compilación → Realtime Database → Crear base de datos.
    2. 
          
  2. Ubicación: Bélgica (europe-west1), para que los datos queden en la Unión Europea.
    3. 
          
  3. Elige modo bloqueado. Las reglas de verdad las pegarás después.
    4. 
          
  4. Arriba verás una dirección que termina en firebasedatabase.app. Si tu firebaseConfig no la trae, añádela como databaseURL.
    5. 
          
  5. Pestaña Reglas: pega las reglas que te da el configurador y pulsa Publicar.
    6. 
        

        
Si alguna vez lees ".read": true, ".write": true para toda la base de datos, no lo publiques: cualquiera con la dirección podría leer y borrar todo.

      

    


    

      
2 bis. Activar FirestoreSolo para ConVive

      

        
    
          
  1. Menú lateral: Compilación → Firestore Database → Crear base de datos.
    2. 
          
  2. Ubicación en Europa (por ejemplo eur3 o europe-west1). No se puede cambiar después.
    3. 
          
  3. Elige modo de producción.
    4. 
          
  4. Pestaña Reglas: pega las reglas que te da el configurador y pulsa Publicar.
    5. 
        

        
ConVive no necesita databaseURL: con el firebaseConfig normal es suficiente.

      

    


    

      
3. Activar el acceso con usuarioAuthentication, para apps con entrada por IdEA

      

        
    
          
  1. Compilación → Authentication → Comenzar.
    2. 
          
  2. Pestaña Sign-in method → Correo electrónico/contraseña → activa solo el primer interruptor → Guardar.
    3. 
          
  3. No hace falta crear usuarios a mano: cada app los crea desde su panel (Teletrabajo en Personal, Evaluaciones en Ajustes → Gestionar profesorado, ConVive en Configuración).
    4. 
        

        
Los "correos" del tipo usuario@micentro.local no existen ni reciben nada: son solo el identificador interno que Firebase necesita.

      

    


    

      
4. Configurar la appCon la pestaña "Configurar para tu centro"

      

        
    
          
  1. Descarga la plantilla desde Las apps y descomprímela.
    2. 
          
  2. Abre Configurar para tu centro y sube el index.html.
    3. 
          
  3. Si la app usa Firebase, pega el firebaseConfig. Después rellena los datos del centro.
    4. 
          
  4. Descarga el index.html configurado y sustituye con él al de la carpeta.
    5. 
          
  5. Copia las reglas y publícalas en Firebase (guía 2, último paso).
    6. 
        

        
Cuadra Horarios, Mis Lecturas, PDF a Markdown y Word y el Troglodita no llevan configuración: úsalos tal cual. ¿Prefieres configurar a mano las demás? Abre el index.html con el Bloc de notas: al principio verás el bloque CONFIGURACIÓN DEL CENTRO. Cambia solo lo que hay entre comillas.

      

    


    

      
5. Publicar en GitHub PagesTu app con dirección web gratuita

      

        
    
          
  1. Crea una cuenta en github.com. Tu nombre de usuario formará parte de la dirección: usuario.github.io.
    2. 
          
  2. Pulsa New repository. Nombre corto y sin espacios (por ejemplo teletrabajo), marca Public y crea el repositorio.
    3. 
          
  3. Pulsa uploading an existing file y arrastra el contenido de la carpeta: index.html, sw.js, manifest.json y los iconos. Después, Commit changes.
    4. 
          
  4. Ve a Settings → Pages. En Branch elige main y la carpeta / (root). Guarda.
    5. 
          
  5. En uno o dos minutos la app estará en https://usuario.github.io/teletrabajo/.
    6. 
        

        
El repositorio es público: cualquiera puede ver el código. Por eso no lleva datos personales. La apiKey que se ve no es una contraseña; lo que protege los datos son las reglas y el acceso con usuario.

      

    


    

      
6. Primera entrada y alta del claustroPara apps con acceso por usuario IdEA

      

        
    
          
  1. Abre la app publicada. La primera vez solo existe la persona administradora que pusiste en el configurador.
    2. 
          
  2. Entra con su usuario IdEA. La cuenta de administración se crea sola esa primera vez.
    3. 
          
  3. Desde el panel de personal de la app, da de alta a cada docente con su nombre y usuario IdEA.
    4. 
          
  4. Comparte la dirección o el código QR con el claustro. Cada persona entra eligiendo su nombre y escribiendo su IdEA.
    5. 
        

        
El usuario IdEA se usa como clave para que nadie tenga que recordar otra contraseña. Es cómodo, pero no es secreto: úsalo para la gestión interna del claustro, no para información sensible.

      

    


    

      
7. Instalar la app en móvil y ordenadorPara abrirla como una app más

      

        
    
          
  1. Android (Chrome): menú ⋮ → Instalar aplicación o Añadir a pantalla de inicio.
    2. 
          
  2. iPhone o iPad (Safari): botón Compartir → Añadir a pantalla de inicio.
    3. 
          
  3. Ordenador (Chrome o Edge): icono de instalar en la barra de direcciones.
    4. 
        

      

    


    

      
8. Actualizar una app ya publicadaCuando salga una versión nueva de la plantilla

      

        
    
          
  1. Descarga la plantilla nueva y pásala por el configurador. Tus datos del centro seguirán guardados en el navegador.
    2. 
          
  2. Pega de nuevo tu firebaseConfig: es el mismo de siempre.
    3. 
          
  3. En GitHub, entra en el repositorio, sube el nuevo index.html y confirma con Commit changes.
    4. 
          
  4. Si las reglas han cambiado, vuelve a publicarlas.
    5. 
        

        
Los datos no se pierden al actualizar: viven en Firebase, no en el archivo.

      

    


    
Cuando algo no funciona


    

      
Sale "Esta app aún no está configurada"

      
Falta algún dato imprescindible en el bloque de configuración: normalmente la apiKey, la databaseURL o el usuario IdEA de la persona administradora. Vuelve a pasar el archivo por el configurador y comprueba que todos los indicadores están en verde.

    

    

      
No guarda o aparece "PERMISSION_DENIED"

      
Casi siempre son las reglas: no se han publicado, se pegaron las de otra app o se publicaron con un IdEA de administración distinto. Copia de nuevo las del configurador, sustituye todo el contenido de la pestaña Reglas y pulsa Publicar.

    

    

      
Error "auth/operation-not-allowed"

      
No está activado el método Correo electrónico/contraseña en Authentication (guía 3).

    

    

      
"La contraseña debe tener al menos 6 caracteres"

      
Firebase no acepta claves de menos de 6 caracteres. Si algún usuario IdEA es más corto, esa persona necesitará una cuenta creada a mano desde la consola, en Authentication → Users.

    

    

      
He subido cambios y sigo viendo la versión antigua

      
GitHub Pages tarda uno o dos minutos en publicar. Después, recarga forzando la actualización (Ctrl + F5 en el ordenador) o cierra y abre la app instalada. Si la app muestra un aviso de nueva versión, púlsalo.

    

    

      
Con la cuenta educativa no me deja entrar en Firebase o Gemini

      
En las cuentas corporativas o educativas, la administración puede tener bloqueados algunos servicios de Google. Crea una cuenta de Google para el centro y úsala solo para esto.

    


    
Datos personales


    

      
Lo mínimo imprescindibleAntes de meter datos de alumnado o familias

      

        
    
          
  1. Nada de nombres, usuarios ni notas escritos dentro del código: el repositorio es público.
    2. 
          
  2. Proyecto de Firebase creado con la cuenta del centro y base de datos en Bélgica (europe-west1).
    3. 
          
  3. Reglas publicadas siempre, y cuentas individuales para quien tenga que escribir.
    4. 
          
  4. Guarda solo lo que la app necesita. Si un dato no se usa, no se pide.
    5. 
          
  5. Si la app va a tratar datos del alumnado, coméntalo con dirección y consulta a la persona delegada de protección de datos de tu administración educativa.
    6. 
        

      

    

  







  

    
Crea la tuya con IA

    
Así nacieron estas apps: conversando. Aquí tienes el método, dos Gems de Gemini listos para montar y los encargos que mejor funcionan.

  


  

    

      
El método

      
    
        
  1. Describe el problema, no la app"Perdemos las autorizaciones de salida" funciona mejor que "hazme un formulario".
    2. 
        
  2. Deja que la IA preguntePídele que te haga preguntas antes de programar. Ahorra muchas vueltas.
    3. 
        
  3. Un único archivoExige siempre el index.html completo. Nada de fragmentos sueltos.
    4. 
        
  4. Prueba, copia el error y pégaloTecla F12 → Consola. Lo que salga en rojo, a la conversación.
    5. 
        
  5. Primero sin base de datosCuando todo funcione, conéctala con Firebase.
    6. 
        
  6. Publica y comparteGitHub Pages y un código QR para el claustro.
    7. 
      

    

    

      
Gem 1: Constructor de apps del cole

      
    
        
  1. Abre gemini.google.com y, en el menú lateral, entra en Gems.
    2. 
        
  2. Pulsa Nueva Gem. Nombre: Constructor de apps del cole.
    3. 
        
  3. Pega las instrucciones de abajo en el cuadro Instrucciones.
    4. 
        
  4. Si te deja elegir herramienta predeterminada, elige Canvas: verás la app funcionando junto a la conversación.
    5. 
        
  5. En Conocimiento, sube como ejemplo el index.html del Troglodita o de Mis Lecturas: son apps completas en un solo archivo.
    6. 
        
  6. Guarda y compártela con el claustro.
    7. 
      

      

        

        
      

      
Las apps que salgan de este Gem usan el mismo bloque de configuración que las plantillas, así que también podrás pasarlas por el configurador.

    

  


  
Gem 2: Soporte de instalación

  

    

      
Un ayudante para después de la formación: responde dudas sobre Firebase, GitHub y los errores más comunes. Créalo igual que el anterior y sube como conocimiento el LEEME.txt de cada app. Así nadie se queda atascado un martes por la tarde.

Recursos

    
La lista de comprobación para dejar una app funcionando en tu centro, el vocabulario de la sesión y los enlaces que vas a necesitar.

  


  
Lista de comprobación

  

  

  
    
  
    
    
    
  
    

  
    Vocabulario
    
  
    
    
    Firebase
    Servicio de Google que pone la base de datos y el acceso con usuario. Tiene un plan gratuito.
    
    
    Realtime Database
    La base de datos que usan casi todas estas apps. Los cambios llegan al instante a todos los dispositivos.
    
    
    Firestore
    Otra base de datos de Firebase, pensada para datos más grandes. Algunas apps la usan en lugar de Realtime Database.
    
    
    Authentication
    La parte de Firebase que comprueba quién entra.
    
    
    Reglas de seguridad
    El texto que dice quién puede leer y escribir cada parte de la base de datos.
    
    
    firebaseConfig y apiKey
    Identifican tu proyecto. No son contraseñas y pueden verse en la web sin problema.
    
    
    GitHub
    Plataforma para guardar código. Cada app vive en un repositorio.
    
    
    GitHub Pages
    La opción de GitHub que convierte un repositorio en una web con dirección propia.
    
    
    PWA
    Web que se puede instalar como una app en el móvil o el ordenador.
    
    
    Service worker
    El archivo sw.js: permite instalar la app y abrirla aunque falle la conexión.
    
    
    Usuario IdEA
    El usuario de Séneca de cada docente. Estas apps lo usan para identificar a cada persona; nunca se pide la contraseña de Séneca.
    
    
    Gem
    Asistente de Gemini con instrucciones guardadas, para no repetirlas en cada conversación.
    
    
    Canvas
    Espacio de Gemini donde se ve y se prueba el código mientras se conversa.
